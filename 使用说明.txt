# SyncXossToOnelap 使用说明

本工具支持三类同步方向：
- OneLap → 其他平台（行者 / 捷安特 / iGPSport / Garmin / Strava）
- 行者(XOSS) → OneLap / iGPSport（行者为数据源，新增）
- iGPSport → OneLap（反向增量补录）

## Windows（打包版）快速开始

1) 解压压缩包到任意目录（建议全英文路径，避免权限问题）

2) 配置文件
   - settings.ini：实际运行配置（你需要填写真实账号密码）
   - settings.ini.example：示例模板（可用来对照/复制）
   - 如果 settings.ini 被覆盖，可复制 settings.ini.example 后重命名为 settings.ini
   - 若只同步到 iGPSport：将 [igpsport] enable_sync = true
   - 若同步到 Garmin：将 [garmin] enable_sync = true，并填写 Garmin Connect 中国区账号密码
   - 若启用 iGPSport → OneLap：将 [igpsport_to_onelap] enable = true
   - 若只想全量下载 OneLap：将 [sync] onelap_full_sync = true
   - 若要把行者当作数据源：将 [sync] data_source = xoss（详见场景 F）

3) 填写账号密码
   - OneLap 必填：[onelap] username/password
   - 其他平台按需填写账号密码并打开开关（见下方场景）

4) 运行程序
   - 双击 SyncXossToOnelap.exe
   - 程序会自动打开浏览器进行登录与上传，请不要关闭浏览器窗口，等待程序结束

## 常用场景与配置

### 场景 A：OneLap → iGPSport（默认增量）

用途：只同步“比基准更新”的 OneLap 记录到 iGPSport（避免重复上传）。

```ini
[igpsport]
enable_sync = true
```

说明：
- 程序会在步骤2尽量从其它平台读取“最新记录时间”作为同步基准，通常表现为增量。
- 如果无法获取任何基准（未配置/登录失败/禁用），会退化为全量。

### 场景 B：OneLap 全量下载并同步（强制全量）

用途：不管任何平台有没有基准，都强制全量拉取 OneLap 活动用于同步。

```ini
[sync]
onelap_full_sync = true
```

### 场景 C：OneLap → Garmin Connect 中国区

用途：将 OneLap 下载出的新增运动文件导入 Garmin Connect 中国区。

```ini
[garmin]
username = 你的Garmin账号
password = 你的Garmin密码
enable_sync = true
max_upload_files = 9
```

说明：
- Garmin 会打开 `https://connect.garmin.cn/app/import-data` 导入页面。
- `max_upload_files` 表示 Garmin 每批最多上传文件数；例如设为 9 时，会按每批最多 9 个持续上传全部增量文件。
- Garmin 会按活动时间从旧到新上传，避免中途异常后下次增量同步漏掉中间记录。
- 如遇验证码、短信验证或二次验证，请在自动打开的浏览器中手动完成。
- Garmin 也可作为增量同步基准，优先级位于 Giant 之后、Strava 之前。

### 场景 D：不需要行者（XOSS）

用途：明确禁用行者同步，避免步骤4进入行者上传流程。

```ini
[xoss]
enable_sync = false
```

### 场景 E：iGPSport → OneLap（反向增量补录）

用途：当 iGPSport 记录比 OneLap 多时，把 iGPSport 中更新的记录补录回 OneLap。

```ini
[igpsport_to_onelap]
enable = true
mode = auto
strategy = time_based
```

说明：
- mode=auto：优先增量补录；当 OneLap 为空或无法获取基准时会自动退化为更大范围同步。

### 场景 F：行者(XOSS) → OneLap / iGPSport（行者为数据源）

用途：主力记录在行者，需要把行者的骑行记录补录到 OneLap 与/或 iGPSport。

```ini
[sync]
data_source = xoss

[xoss]
username = 行者手机号
password = 行者密码
time_offset_hours = 8
prefer_fit = true
dry_run = false
login_mode = auto

[onelap]
username = 顽鹿账号
password = 顽鹿密码

[igpsport]
username = iGPSport账号
password = iGPSport密码
enable_sync = true
```

说明：
- 设为 xoss 后，程序不再以 OneLap 为下载源，而是登录行者 → 导出 Fit → 上传到 OneLap / iGPSport。
- 首次使用建议先把 [xoss] dry_run 设为 true：程序只登录行者并下载记录到 downloads/xoss，不上传任何数据；
  此时即使还没配好 OneLap / iGPSport 也能验证（无基准时只取最近 10 条）。确认下载的时间、距离、文件都正常后再改为 false。
- 行者的“导出Fit”必须该记录来自设备（详情里 equipment_info 非空）；否则只会尝试 GPX，而 GPX 不能直传 OneLap。
- 增量：以两个目标平台最新记录时间中更早的一个作为下载下限，逐平台判断是否跳过。
- 去重：成功记录写入 xoss_sync_state.json，重复运行不会重复上传。
- 两个目标平台都读不到基准时间时程序会终止，确认要全量同步时设置 [sync] onelap_full_sync = true。
- 排查接口问题可运行：python xoss_source_probe.py --cookie "sessionid=xxxx"

## 下载与文件目录

- 默认下载目录：settings.ini 中 [sync] storage_dir
- 支持文件类型：supported_formats（默认 .fit/.gpx/.tcx）

## 常见问题（FAQ）

### 1) iGPSport 上传数量限制

- iGPSport 网页端通常一次最多导入 9 个文件
- 程序会自动分批上传

### 2) 浏览器登录相关

- 首次运行需要浏览器完成登录（可能遇到验证码/短信验证）
- 登录时请不要关闭自动打开的浏览器窗口

### 3) 增量同步端口问题

- 程序已使用 auto_port 方式启动浏览器，避免默认 9222 端口冲突

## 安全提示

- settings.ini 含账号密码，请勿提交到公开仓库或分享给他人
- 建议只在本机保存配置文件，并定期更换平台密码
